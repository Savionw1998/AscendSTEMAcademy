# Fix plan for ascendstemacademy.com

This is the work order that goes with `docs/site-audit-2026-09-29.md`. It is written for a
Claude Code session. Work through the tasks in order. Each task says what to change, where,
and how to prove it worked.

## Before you start

**Access you need**

- The "Ascend STEM Academy MCP" connector (Royal MCP) for pages, post meta, menus and
  rendered-page checks.
- Shell access to the WordPress host (SSH with `wp` CLI, or the HostGator file manager) for
  WooCommerce options, plugin removal and files under `wp-content`. The MCP connector
  cannot write WooCommerce options.
- The Gmail connector for ascendstemacademy@gmail.com to confirm emails arrive.

If a task needs access you do not have, skip it, and list it under "Left for the owner" in
your final report. Do not look for workarounds.

**The owner authorizes** every change listed below, including the deletions and plugin
removals, but nothing outside this list. Earlier sessions were blocked from deleting posts
and from editing the /user/ page. If the permission prompt appears, that is expected; ask
the user to approve it.

**Ground rules**

1. Take a fresh UpdraftPlus backup first (UpdraftPlus → Backup Now, database and files) and
   confirm it finished.
2. Read the current value before every write. If it does not match what this plan expects,
   stop that task and report the difference.
3. After every page or meta change, check it with `wp_verify_rendered_page`. Add a
   cache-busting query string such as `?v=fix1`, because W3 Total Cache can serve stale
   HTML.
4. Keep every undo token the connector returns, and list them in your final report.
5. When editing `_elementor_data`, send the value as structured JSON, not a string. Then
   read it back and confirm inline `<script>` and `<style>` blocks survived. If the
   connector stripped them, restore with the undo token and leave that edit for the owner.
6. Never deactivate or delete WooCommerce, WooPayments, Ultimate Member, WP Mail SMTP,
   Wordfence, UpdraftPlus, Jetpack, the Ascend plugins, or the Astra and Astra Child
   themes.

## Phase 2: the withdrawal letter generator never emails anyone

**Cause.** The generator on the Enrollment page (ID 2781, Elementor HTML widget `14ec01f`)
runs entirely in the browser. `generateLetter()` fills `#letterPaper`, then offers Print and
Copy. It has no email field and makes no request, so neither the school nor the parent ever
gets an email. The Compliance Wizard on the Home page does send emails, because the Ascend
Lead Capture plugin (v1.7.0) adds its own "email me a copy" step there. The plugin's
description says it handles the Withdrawal Letter Generator too, so its hook probably
targets markup that changed when the Enrollment page was redesigned.

**Fix.**
1. Get the source of `wp-content/plugins/ascend-lead-capture/` from the server. Find:
   - how it attaches to the Compliance Wizard, and to the withdrawal generator if that code
     exists: the selectors it looks for, and the JS file;
   - the AJAX action or REST route it posts to, its nonce, and its fields (email, name,
     source, page, body).
2. Choose the smaller fix:
   - **A (preferred):** update the plugin's generator hook to the current markup. It should
     run after `#generateBtn` succeeds and show the same email step the wizard uses. It
     should send `source = "Withdrawal Letter Generator"` and use the text of `#letterPaper`
     as the body. Bump the plugin version.
   - **B:** add an "Email me a copy" email input and button inside `#letterOutput` in the
     Enrollment widget, posting to the same endpoint with the same fields.
3. Both emails must be sent. The school gets `notify_email = ascendstemacademy@gmail.com`,
   subject "[Lead] Withdrawal Letter Generator - <parent email>". The parent gets their own
   copy (`email_parent` is already on in `ascend_lc_settings`).

**Verify.** Submit the generator with parent email `ascendstemacademy+wlgtest@gmail.com`.
In Gmail, confirm both messages arrived and that a new `ascend_lead` post exists with the
source "Withdrawal Letter Generator". Then delete that test lead.

## Phase 6: retire Elementor (last, and one page at a time)

Only start this after Phases 1–5 are done and verified. Astra stays.

Nearly every Elementor page is a single Elementor HTML widget holding hand-written HTML
(the "design v2" pages). Converting a page means:
1. Read `_elementor_data`, and join the HTML of its widgets in order. For shortcode widgets,
   take the shortcode text.
2. Write that into `post_content` as `<!-- wp:html -->…<!-- /wp:html -->` blocks, with
   shortcodes in `<!-- wp:shortcode -->` blocks.
3. Delete the `_elementor_edit_mode` meta. This is how the Enrollment Agreement (4448) was
   fixed on 29 Sep.
4. Verify with `wp_verify_rendered_page`: same h1, the key selector present, HTTP 200. The
   restore path is `wp_update_post_meta` with `_elementor_edit_mode = builder`.

5477, 3521, 4303, 4304, 4307, 4308, 4302, 6097, 5952, 5982, 6011, 6017, 3477, 3517.
